## Architecture Decisions Made This Session

### Two application systems coexist
- **Legacy system:** student applies at `/opportunities/:slug/apply` → `hospital_applications` table. BCS Free Health Clinic uses this.
- **New position system:** student applies at `/apply/:positionId` → `student_applications` table. Newer hospitals use this.

`useAllApplications` hook fetches both and merges into one array. Legacy apps have `_isLegacy: true` marker.

### Pipeline status (frontend: PascalCase, DB: enum)
`OpportunityStatus` uses PascalCase values: `"Saved" | "Researching" | "Applied" | "Waiting" | "Interview" | "Accepted" | "Rejected" | "Archived"`. The DB migration adds a `pipeline_status_enum` that mirrors these. The Select dropdown on tracker cards already implements all 8 states.

### localStorage keys in use
| Key | Purpose |
|---|---|
| `ch_onboarding_done` | Flag: first-visit modal shown |
| `ch_apply_year` | Student's intended application year |
| `ch_hours_goal` | Student's hours goal (default 300) |
| `clinicalhours_checklist_dismissed` | Activation checklist hidden |
| `clinicalhours_location_prompt_dismissed` | Location banner hidden (sessionStorage) |

### RLS patterns — critical
- **BROKEN (causes silent empty results):** `(SELECT email FROM auth.users WHERE id = auth.uid())`
- **CORRECT:** `auth.email()`
- Profiles table has NO `role` column — roles live in `user_roles`. Admin check = `public.has_role(auth.uid(), 'admin')`

### Highest value (implement next)

1. **Apply SQL migrations** — Pipeline status migration (`20260531100000`) will unlock the full tracker UX. Trust metadata migration will make TrustChips show real data. Apply both via Supabase SQL Editor.

2. **Q&A RLS fix** — The Q&A tab loading forever is visible to every student who opens an opportunity detail page. Investigate `questions` table RLS, likely missing `allow select for all` policy.

3. **Streak / weekly engagement mechanic** — The `HoursGoalWidget` exists but there's no reward for consistent logging. A "weekly streak" counter (consecutive weeks with any logged hour) would drive habitual return behavior. Data already available in `experience_entries`.

4. **Onboarding → first opportunity funnel** — After the modal closes, route the student directly to `/opportunities` with a contextual "Here are opportunities near you" highlight. Currently the modal just closes to wherever they were.

### Medium priority

6. **AMCAS activity description drafts** — Journal reflections stored in `experience_entries` could be transformed into 700-char AMCAS-ready descriptions via an AI prompt. High perceived value, medium effort.

7. **Competitiveness benchmarking widget** — Compare student's hours to AAMC MSAR data for their target tier. Requires either a static data table or a Supabase table seeded with school averages.

8. **Mobile hamburger bug** — The homepage on mobile renders the app nav (Track, Opportunities, Applications) instead of the marketing nav (Home, Map, Contact, Login). The two navbars are separate components but the wrong one is showing on `/` mobile.
